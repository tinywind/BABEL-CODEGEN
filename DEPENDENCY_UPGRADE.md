# Dependency upgrade

The compiler and Maven plugin require Java 17. The Maven coordinates, `generate` goal, `babel-codegen` goal prefix, XML namespace, generated JAXB fluent API, and `REACT`/`ES_2015` preset values remain unchanged. Compiler output can differ because Babel has changed; consumers should compare behavior instead of generated bytes.

The embedded compiler is the official `@babel/standalone` 7.29.11 distribution. Its built-in React and ES2015 presets run on Nashorn 15.7 in ES6 mode. The official core-js-bundle 3.51.0 distribution supplies missing standard functions inside that private compiler engine. It is not inserted into generated application files. A small console adapter sends log/info/debug messages to the engine output and warn/error messages to Java stderr.

Both JavaScript distributions retain their upstream MIT licenses under `META-INF/licenses`. Their exact registry tarball integrity and script SHA-256 values are recorded under `META-INF`. The files are loaded from the packaged JAR; compilation needs no network access or Node.js installation.

JAXB 2.3 retains the existing `javax.xml.bind` model and XML contract on Java 17. The former jOOQ dependency was used only for a string adapter. The local adapter preserves trimming and `${system.property}` substitution, including unresolved placeholders. Maven API and core now use one 3.10.0 version, with patched Plexus and Guava dependencies.

`recursive=false` now processes top-level inputs and leaves nested inputs alone. `overwrite=false` preserves existing output and still creates missing files. Tests reproduced both option failures in the original Java 8 implementation before the two corrections.

Verification includes real JSX transformation, execution of generated ES2015 code, UTF-8 text, recursive and overwrite options, and JAXB round trips. Separate packaged-artifact checks execute both CLI presets and the actual Maven goal, including its skip option, against the original Java 8 artifacts and the Java 17 candidate. Node.js checks the generated syntax and executes the ES2015 output.

The original invalid-source policy remains: a syntax error is printed and no output file is created, but the Maven goal can still exit successfully. The same negative input was checked against both versions. Consumers must inspect diagnostics and expected outputs when handling invalid input.

Babel 6 has no patched release for [GHSA-67hx-6x53-jw92](https://github.com/advisories/GHSA-67hx-6x53-jw92). This migration retires that compiler; it does not claim the existing preset configuration demonstrated exploitation. The [Babel standalone documentation](https://babeljs.io/docs/babel-standalone) describes embedded non-Node environments, and [core-js](https://github.com/zloirock/core-js) provides the standard-library implementation used by this engine.
