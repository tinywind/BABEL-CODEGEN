# Runtime and plugin compatibility

Version 0.2.1 requires Java 21. The Maven coordinates `org.tinywind:babel-codegen` and `org.tinywind:babel-codegen-maven`, Maven goal `generate`, goal prefix `babel-codegen`, existing configuration XML namespace, JAXB fluent API, and `REACT`/`ES_2015` values remain available.

## Compiler runtime

The compiler embeds the official `@babel/standalone` 8.0.10 distribution and uses `org.graalvm.polyglot:polyglot` and `org.graalvm.polyglot:js` 25.4.4.1.1. It loads Babel from the packaged JAR. Node.js and network access are unnecessary during compilation after the Java dependencies have been resolved.

GraalJS contexts deny Java host access and host class lookup. The compiler closes each context after success or failure, including initialization failures. Nashorn and its console/core-js compatibility resources have been removed.

The Babel archive was obtained through the in-app browser. Its SHA-512 integrity was checked against the official npm registry metadata; the bundled script and license were checked against that archive. `META-INF/babel-standalone.properties` records the exact version, registry tarball integrity and script SHA-256. The upstream MIT license remains under `META-INF/licenses`.

Babel 8 changes the default React runtime. This integration explicitly selects the classic runtime for `REACT`. `ES_2015` maps to `env` with an IE 11 syntax target, CommonJS modules and no external Browserslist configuration. Forcing every Babel transform would also enable ES3 reserved-word renaming; the explicit target preserves identifiers such as `double`. Generated bytes can change, so compatibility tests check behavior.

Jakarta XML Binding API 4.0.5 and runtime 4.0.9 replace JAXB 2.3. The configuration model remains in `org.tinywind.babelcodegen.jaxb`, with the same XML namespace, fluent methods and collection setter. Java code that uses JAXB directly or extends `XmlAdapter` must migrate from `javax.xml.bind` to `jakarta.xml.bind`. Maven and Gradle configuration syntax stays the same.

JAXB Tools 4.0.16 supplies the source generator, element-wrapper, setter, fluent, default-value and annotation plugins. These maintained plugins replace the legacy XEW and JAXB2 Commons artifacts. Collection setters use direct assignment after wrapper transformation to retain `setSources(List<Source>)`; annotation bindings target retained types. Binding documents use the Jakarta 3.0 binding namespace and current Annox namespace. The application configuration namespace is unchanged.

Maven API/core 3.10.0 dependencies are provided by Maven and are not transitive application runtime dependencies. The plugin POM and generated descriptor declare Maven 3.10.0; Java 21 remains the runtime floor. Maven 4 release candidates are excluded from stable-version upgrades.

## Failures and exclusions

Generation fails on invalid configuration, unreadable or missing input roots, output directory failures and syntax errors. Maven propagates these failures as `MojoExecutionException`, Gradle as `GradleException`, and the CLI as a nonzero exit code. Configuration XML validation errors are rejected. Existing output is preserved when that input has a syntax error; generation is not a transaction across every input.

Exclusions are case-sensitive Ant patterns, relative to each input root. Comma-separated Maven patterns and Gradle lists support root/nested files and directories. Excluded inputs are not parsed. Existing recursive and overwrite options apply in both plugins.

## Gradle plugin

Plugin ID: `org.tinywind.babel-codegen`, version `0.2.1`. Implementation artifact: `org.tinywind:babel-codegen-gradle-plugin:0.2.1`.

The native Java Gradle project shares the Maven-built compiler. The `babelCodegen` extension and task use Gradle properties and named sources. Inputs and output directories participate in up-to-date checks, and the task supports configuration-cache reuse. Build caching is disabled by default because preserving existing output with `overwrite=false` makes that output depend on its prior contents.

The Gradle wrapper pins distribution 9.8.2 and its SHA-256. There is no external Kotlin Gradle plugin dependency. Gradle 8.6 consumers use Java 21; Java 25 consumers use Gradle 9.8.2. Upstream libraries can emit native-access and Unsafe deprecation warnings on Java 25.

## Verification and publication

Tests use JUnit Jupiter 6.1.3 with `@TempDir`; Maven and Gradle both execute the current JUnit Platform. Tests cover JSX and executable ES2015 output, UTF-8 text, XML contracts, recursive/overwrite/exclusion behavior, failures and CLI exit codes. Maven Invoker tests run real consumers through generation and resource packaging and verify negative builds and skip. Gradle TestKit covers both DSLs, generated resources in a JAR, configuration-cache reuse, multiple sources, recursion, overwrite, exclusions and failure handling.

The Maven wrapper pins Maven 3.10.0 with a SHA-256 check; CI uses this wrapper instead of the runner's preinstalled Maven. GitHub CI verifies Java 21 and 25. CodeQL builds both Java adapters and the shared compiler; intentionally invalid JavaScript fixture inputs are excluded from JavaScript extraction.

Maven Central publication uses signed parent/compiler/Maven plugin artifacts. The release profile uses the Central Publishing plugin with server ID `central`; it replaces the retired OSSRH endpoints. The Gradle project publishes through the Gradle Plugin Portal. Publishing credentials stay outside the repository.
